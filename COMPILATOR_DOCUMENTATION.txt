1. SYSTEM OVERVIEW & ARCHITECTURAL PHILOSOPHY
================================================================================

Compilator is a hybrid desktop artificial intelligence assistant and operating 
system automation orchestrator. It bridges high-level human natural language 
(English, Hindi/Hinglish) with low-level Windows execution (Winget packaging, 
PowerShell scripting, Python execution, file system management, and telemetry).

Key Design Tenets:
- Privacy First & Local Capable: Capable of running 100% offline using local LLMs 
  (Ollama, LM Studio) or deterministic rule-based planning when no AI key is present.
- Non-Blocking Asynchronous Execution: Long-running system tasks (software installs, 
  heavy Python scripts, directory scans) run in dedicated child processes with 
  streaming stdout/stderr logs piped directly to the user interface.
- Zero Ghost Data: Real statistics derived strictly from disk-persisted history 
  and active state—no hardcoded placeholders or mock metrics.
- Fail-Safe Sandboxing: Strict validation on executable paths, drive roots, and 
  PowerShell syntax to prevent accidental injection or command corruption.

3. COMPLETE FEATURE & UI MATRIX
================================================================================

3.1 WINDOW MANAGEMENT & SIDEBAR MODES
-------------------------------------
- Frameless Window with Custom Titlebar: Minimize, Maximize/Restore, Close controls.
- Docked Sidebar Mode:
  * IPC Channel: 'window:sidebar-mode'
  * Snaps Compilator into a 400px-wide sidebar pinned to the right edge of the screen.
  * Sets window to 'alwaysOnTop', allowing it to float beside IDEs, browser windows,
    or games for continuous co-pilot assistance.
- Normal Mode:
  * Restores window to a centered 1280x840 work desktop.

3.2 HOME DASHBOARD & REAL ANALYTICS
-----------------------------------
- Personalized Header: Dynamic user greetings ("Welcome back, Preet").
- Accurate Stat Cards:
  * Total Tasks (All-time recorded from disk store).
  * Completed Tasks (Count of successfully finished operations).
  * Failed Tasks (Count of aborted or error-terminated runs).
  * Active Tasks (Current pending or running jobs).
- Daily Progress Widget:
  * Dynamic visual completion gauge showing completed/total for today's tasks.
- Interactive Analytics Chart (Chart.js / react-chartjs-2):
  * Dynamic bar and doughnut charts analyzing task distributions by type 
    (winget_install, run_python, run_powershell, mkdir, write_file) and outcomes.

3.3 INTERACTIVE TASK QUEUE & ERROR RECOVERY
-------------------------------------------
- Lifecycle Status Badges:
  * Pending (Grey): Queued for execution.
  * Running (Amber animated): Currently active child process.
  * Completed (Emerald): Finished with exitCode 0.
  * Failed (Crimson): Exited with error code or stderr output.
  * Cancelled (Slate): Aborted by user request.
  * Already Installed (Teal): Winget package already confirmed in system.
- Per-Task Controls:
  * "Run Now" / "Cancel" triggers.
  * Error Recovery Retry Button: Appears automatically on failed/cancelled tasks 
    to clone the task parameters and re-enqueue a fresh attempt.
  * "View Report" Action: Opens formatted markdown/HTML execution logs in the 
    native system browser/editor.

3.4 NATURAL LANGUAGE AI PLANNER & DETERMINISTIC FALLBACK
--------------------------------------------------------
- Conversational Task Generation: Accepts casual prompts like:
  * "prepare my AI development pc" -> Plans git, python, vscode, nodejs.
  * "create folder C:/AI and write file test.py" -> Generates mkdir + write_file.
  * "yr chrome install krde bhai" -> Accurately resolves Google.Chrome.
- Safe Negation Handling: Built-in parser immediately blocks execution on phrases 
  like "don't install", "cancel install", "never mind", "I changed my mind".
- 100% Offline Fallback: If AI is unreachable, `src/planner-core.js` analyzes the 
  prompt using deterministic regex tokenizers and resolves known software targets.

3.5 DRAG-AND-DROP SCRIPT RUNNER
-------------------------------
- Drop Zone: Drop any `.py` (Python) or `.ps1` (PowerShell) file anywhere into the app.
- Automatic Task Creation: Compilator reads file path, detects type, labels the 
  action, and queues a `run_python` or `run_powershell` task immediately.

3.6 SOFTWARE CATALOG & BULK PROVISIONER

3.9 TASK PERSISTENCE & SEARCHABLE HISTORY

  * Filter dropdowns: Status (Completed/Failed) and Task Type.

4. SUPPORTED TASK ENGINE EXECUTORS
================================================================================

Compilator's main process (`main.cjs`) implements low-level execution handlers:

1. `winget_install`:
   - Command: `winget install --id <ID> -e --silent --accept-package-agreements --accept-source-agreements`
   - Detects pre-installed packages to avoid redundant downloads.
   - Streams live installation progress.

2. `winget_list`:
   - Command: `winget list`
   - Enumerates software inventory on the host system.

3. `run_python`:
   - Command: `python -u <scriptPath>` (or direct python interpreter execution)
   - Real-time stdout and stderr piping.

4. `run_powershell`:
   - Command: `powershell.exe -NoProfile -ExecutionPolicy Bypass -File <scriptPath>`
   - Allows safe administration and automation scripts to run without script execution policy blocks.

5. `mkdir`:
   - Creates recursive directories via Node `fs.mkdirSync(dir, { recursive: true })`.

6. `write_file`:
   - Writes configurations, source scripts, or markdown documents with UTF-8 encoding.

7. `list_exe_files`:
   - High-speed drive root indexing with path traversal security checks.

6. SECURITY & SECRETS ARCHITECTURE
================================================================================

Compilator enforces strict credential isolation:
- No Hardcoded Secrets: All secrets are strictly stripped from `package.json`, 
  scripts, and renderer bundles.
- Automatic Git Ignoring: `.env`, `.env.local`, and build artifacts are blocked 
  in `.gitignore`.
- Dual Environment Loader: Both `run-electron.cjs` and `main.cjs` parse `.env` 
  at startup without requiring third-party runtime dependencies.
- Process Environment Scrubbing: `run-electron.cjs` scrubs `ELECTRON_RUN_AS_NODE` 
  from the environment before spawning Electron, ensuring compatibility with 
  IDE-hosted terminal sessions.

8. RUNNING & BUILDING COMPILATOR
================================================================================

Requirements:
- Windows 10 or 11
- Node.js v20+ (Node.js v24 recommended)
- Python 3.10+ (for Python script execution tasks)
- Winget (Windows Package Manager, included by default in Windows 11)

Development Mode:
  1. Copy `.env.example` to `.env` and insert your API key:
     `Copy-Item .env.example .env`
  2. Launch development mode (starts Vite + Electron with HMR):
     `npm run dev`

Running Unit Tests:
  `npm test` (Runs 202 test assertions against intent parsing and safety)

Production Build:
  `npm run build` (TypeScript check via `tsc -b` and Vite bundle compilation)
